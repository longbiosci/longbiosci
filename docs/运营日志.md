### 一、实证：用 09-25 期卡片验证现有通道有没有盲区

|---|---|

| 修正版（≥2 词命中才算已收录） | 4 条真漏收（多出 N10 BMAL1-YAP） |
| 手工核实 BMAL1 | 命中的是**完全不同的另一篇**（BMAL1-Macrophage-Inflammation-Carcinogenesis） |

### 二、建台账：让「该有的都有吗」变成可回答的问题

新建 `scripts/ledger.py` —— **双向对账**：
- **产出侧**：产出文件里声称收录的全部条目（按 DOI / 标题指纹归一，跨期重复合并）
- **上站侧**：`news/*.html` 实际存在的全部文章
- **对账**：① 产出有、上站无 → **漏收**（必须逐条处置）② 上站有、产出无 → **孤站**（可接受但要计数）

首轮结果：产出条目 187 条（跨期去重后）· 已收录 23 · **漏收 164**。
164 这个数字不可能是真的——N1 `Contractile myografts`（前一轮亲手写过的文章）就在里面。

### 三、排查：三个真实缺口，一个比一个基础

**缺口 1：DOI 索引根本没建，站内自己查不了自己。**
站内 411 篇中 137–141 篇（33–34%）正文不含 DOI，DOI 这条最可靠的查重路径对它们完全失效。
→ 新建 `scripts/backfill-doi.py`：从正文回填DOI 字段（**只增字段，不改任何其他内容**）
并生成 `data/doi-index.json`（DOI → slug 权威索引）。实测补入 274 篇 / 248 条映射。

**缺口 2：DOI 正则太贪婪，站内自己建的索引就是脏的。**
原正则 `10\.\d{4,9}/[^\s"'<>&]+` 会把 `10.1016/j.ymthe.2026.05.025）·研究：MIT`
整段当成 DOI。**这意味着 DOI 精确匹配对站内自己都失效。**
→ 改为 Crossref 合法字符集 `[-._;()/:a-z0-9<>\[\]+]+`。索引条目 248 → 260（多出 12 条是被截断后恢复的）。

**缺口 3：Markdown 链接污染 DOI。**
产出里 DOI 常写成 `[10.1038/xxx](https://doi.org/10.1038/xxx)`，
正则会把后半段 URL 一起吞进来。→ 先剥 `](...)` 再匹配。**这一个 bug 单独造成约 10 条假漏收。**

### 四、第 4 路查重：绕开「中文译名」这个无解的盲区

站内 `<title>` 是中文译名，产出给的是英文原标题，3-gram 相似度实测**普遍 0.00**。
这是结构性的，靠维护中文对照表解决不了。

**但站内 slug 是英文 kebab-case**——`Contractile-Myografts-Systemic-AntiAging-Nature-Aging-2026.html`
与英文原标题天然可比。

→ 新增第 4 路：**英文原标题 vs 站内英文 slug 的词元重叠**。
停用词表剔除 `aging` / `longevity` / `cell` / `human` / `html` 等无区分度词，
判定阈值「命中≥3 词且重叠率≥0.5」（分母取较小集合，避免长标题被短 slug 稀释）。

实测：N1 `Contractile myografts…` 立刻命中（0.5，命中 contractile/myografts/systemic）。
这条路的价值在于**不需要任何人工维护的映射表**。

查重口径由三路扩为**四路**，每条结论仍带 confidence：`high` / `medium` / `low` / `none`。
`confidence=none` 一律标「需人工核对」而不是武断判漏收。

### 三、去记忆化：三层状态（本轮核心改动）

| 层 | 文件 | 作用 |
|---|---|---|
| **事实源** | `data/intake-manifest.tsv` | 网盘四目录全量清单，每次重建，含 size/mtime |
| **游标** | `data/intake-cursor.json` | 每个产出文件的处理状态（pending/done/empty），幂等 |
| **触发** | automation `12409847` | 每 4 小时：读游标 → 扫目录 → 消化 → 推游标 |

```bash
python3 scripts/cursor.py verify --repo .   # 清单与游标是否对齐
python3 scripts/cursor.py next   --repo .   # 待处理（含 why：空文件/游标无记录）
python3 scripts/cursor.py stat   --repo .   # 各层进度 + 空文件告警
```

## 2026-10-19 · 收尾自检发现的三个「工具自己不确定」缺陷（任务 12409847 补记）

收尾自检要求 `cursor.py verify` / `ledger.py audit` / `run-pipeline.sh` 三项全绿。
本轮 `run-pipeline.sh` 一次就绿了，但 `ledger.py audit` 暴露出三个更深的问题——
它们的共同点是：**工具安静地给出一个每次都不一样的答案**。这与本项目反复遇到的
「最大的敌人不是没检查，而是读了不该读的旧东西还不报错」是同一类病。

### (一) 审计计数每次跑都不一样

| 现象 | 同一份数据连跑 `ledger.py audit`，「已收录/漏收」在 173/177、171/179、172/178 之间跳 |
|---|---|
| 根因 | `slugs` 是 **set**，`ledger.py` 与 `harvest.py` 都直接 `for slug in slugs` 迭代它。set 的迭代顺序受 `PYTHONHASHSEED` 影响 |
| 为何会翻转结论 | 查重取「分数最高的那个 slug」，并列时赢家不唯一；而判据里含 `len(inter) >= 3`，赢家不同则重叠词数不同 → 判定翻转 |
| 处置 | 两处均改为 `sorted(slugs)`。现稳定为 **345 / 已收录 172 / 漏收 173**，连跑一致 |

> 审计工具自己不可复现，它就没资格当收尾自检——绿不绿全看你这次运气好不好。

### (二) 对账结果取决于沙箱里恰好躺着什么文件

`.intake/raw/` 被 `audit` 当成产出文件目录全量扫入。但该目录里不只有产出副本，
还混着**运营日志（132 KB，满屏 markdown 表格）、运营待办清单、README、站点评估**。
它们一旦被当作产出入口解析，对账数字就随暂存目录内容漂移；而 `.intake/` 是
gitignore 的、不进版本库 —— 等于对账结果在任何两台机器上都不一样。

→ 改为**默认只告警、不入账**（打印「另发现 N 个 .intake/raw/*.md（未 build 进台账）」），
确认它们确实都是产出文件时才加 `--include-unbuilt`。

### (三) `build` 会静默抹掉历史

`ledger.py build` 是整文件覆写 `data/ledger-outputs.json`。而 `.intake/raw/` 换一个
沙箱就空了，历史产出的原件再也拿不回来——**build 一次，前几轮的记录就凭空消失**。
实测：台账里 5 个历史产出文件的原件均不在本沙箱。

→ 新增 `--merge` 合并模式。产出台账是**累积账，不是快照**。
已用 `--merge` 补录本沙箱 21 个真实产出文件：**文件 5→26、条目 187→345，历史零丢失**。

### (四) 附带的两个收获

- **`ndupload.py` 的假成功**：COS 签名出错时返回 `exit=0` + 空 stderr + XML `<Error>` 正文。
  原判据只看 `returncode`/`stderr`，会把「签名错 → 内容根本没传上去」判成上传成功，
  然后照常落库 —— 网盘里存的还是旧内容。已加 XML 错误体检测。
  （本轮手工转写 1682 字符的签名 URL 时连错两次，正是不该让人碰签名的活证据。）
- **`github.com:443` 又被阻断**：`git push` 连接超时 134 s，而 `api.github.com` 正常。
  已用 `scripts/push_via_api.py` 走 API 通道推送（`force=false`，绝不覆盖他人提交）。

### (五) 一条方法论

这三处都不是「算错了」，而是**在不确定的输入上给出了确定的输出**。
审计、查重、上传确认这类「最后一关」的工具，必须自己先可复现，
否则它的绿灯只是在给流程盖章，不是在给结论背书。

### 七、推送落地与线上核验（收官）

嵌套路径会自动展开——于是请求数从「每目录一次」降到 **4 次 + N 个 blob**：

| 环节 | 结果 |
|---|---|
| 基准断言 | 本地快照 tree == 远端 tree（`060d6849`）✓ |
| 变更集 | 新增 11 / 修改 75 / 删除 **0** |

| tree 校验 | API 建出的 tree sha == 本地 `HEAD^{tree}`（`1cae0a04`）✓ |
| 提交 | `b7d08ea`，parents=[`3b59970d`]，**未强推** |
| ref 更新 | `PATCH /git/refs/heads/main`，**`force: false`** |

最后一步的 tree sha 强校验值得留着：**对不上就中止，不创建提交**。
