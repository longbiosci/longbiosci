# 产业板块重构规划（2026-10-18）

> 目标：把产业板块从「手写名录」改造成「**事件流驱动的公司档案**」，
> 让每条断言都自带来源，让页面由数据生成，让新增情报自动上线。
>
> 本文只做规划，不含已执行的改动。

## 一、现状诊断：三段全断

| 现象 | 证据 |
|---|---|

→ 消化是**事件驱动的人工动作**，不是每周自动跑的管线。上游产出越多，欠账越多。

### 1.3 展示端：坏（已被本次两轮清理证实）

| 页面 | 状态 | 已查出的硬伤 |

| `/investors/` | 🔴 无数据源、无生成器 | 5 条中 3 条有问题（Peter Berg 应为 Peter Thiel、Tony Wyss 身份错配、**Krispy Kreme 家族办公室查无实据**）——已清理 |

没有任何数据源与生成器。写下去那天就是错误的开始。

## 二、定位：产业板块该是什么

用户是**衰老与长寿领域研究者**，工作阶段明确包含「投融资、公司管线、临床进展、监管动态」。
因此产业板块的价值不是"公司介绍页"，而是：

> **一份可核查的长寿产业事件档案**——谁拿了钱、谁被收购、哪个管线推进了、监管口径怎么变。

判断依据（来自现有内容）：
- 全站 553 篇中行业动态仅 **22 篇（4%）**，但已出现高价值选题：
  TAME 迟迟未入组、FDA 把「衰老与长寿」写进监管科学议程、中国明确「衰老非疾病」、
  Genentech 11.7 亿美元接手 Alector 帕金森项目。
- 这些是**研究者真正需要、而媒体不写的**东西。

→ 定位结论：**做深，不做宽**。宁可只做实一个「产业事件流」，也不要四个半空的名录页。

## 三、核心设计：事件流驱动

### 3.1 原则（承接已提炼的纪律 5）

> **公司卡片只存「不随时间变」的属性；所有会变的事实一律来自事件流。**

| 存进静态表（稳定） | 来自事件流（会变） |
|---|---|
| 公司名、别名、技术方向标签 | 融资额、轮次、出资方 |
| 机构名、类型 | 收购方、收购金额、时间 |
| 会议名、主办方 | 日期、地点、是否已过期 |

**每条事件必须带 `source`**。没有来源的事件进不了库——
这从机制上杜绝了「Krispy Kreme 家族办公室」这类杜撰。

### 3.2 数据模型（新建 `data/industry.json`）

```jsonc
{
  "schema": 1,
  "events": [
    {
      "id": "ev-2026-10-001",
      "date": "2026-10-15",
      "type": "融资",            // 融资 | 收购 | 临床 | 监管 | 合作 | 产品 | 管线
      "entity": "Sava Technologies",
      "entity_type": "company",   // company | investor | regulator | conference
      "headline": "B 轮 3600 万美元",
      "amount": "3600 万美元",    // 可选
      "round": "B",               // 可选
      "counterparty": "Ascensia（欧洲分销）",  // 可选
      "evidence": "C",            // 沿用全站 A/B/C 分级
      "source": "行业情报周报_2026-10-14.md",  // 必填
      "source_url": "",           // 可选
      "article_slug": ""          // 关联已有文章（若已单独成文）
    }
  ],
  "companies": [
    { "name": "NewLimit", "aliases": [], "focus": ["部分表观遗传重编程"], "status": "active" }
  ],
  "investors": [
    { "name": "Peter Thiel", "via": "Founders Fund" }
  ],
  "conferences": [
    { "name": "AGE 年度会议", "organizer": "American Aging Association",
      "start": "2026-10-15", "place": "美国·亚特兰大", "source": "" }
  ]
}
```

### 3.3 页面重构

| 页面 | 处置 | 说明 |
|---|---|---|
| **`/companies/`** | **重建为生成产物** | 由 events 按 entity 聚合：每张卡片显示公司名 + 最新 3 条事件 + 每条的来源。卡片里不再出现任何无来源数字 |
| **`/industry/`（新）** | **新建，事件流主页面** | 时间线 + 按类型筛选（融资/收购/临床/监管）。这是产业板块的新入口，替代零散的名录页 |
| `/investors/` | **并入 companies** | 出资人作为事件字段展示（`counterparty` / `via`）。独立成页价值不足，且历史错误率最高 |
| `/papers/` | **砍掉或重建** | 5 篇撑不起「论文库」。要么删页，要么改由 `articles.json` 自动生成「高证据等级论文索引」（A 级优先） |
| `/events/` | **保留并自动化** | 接 `conferences` 表，按当前日期自动标注「已结束」，不再手工 |

## 四、管线接入

在现有 13 环节管线中**新增 1 环节**：

```
1  build-index   2  sync-evidence   3  gen-home   4  gen-topic-pages
5  gen-news-index 6 gen-evidence-pages 7 rebuild-sitemap 8 add-rss
9  inject-poster 10 sync-search-index 11 refresh_counts
12 audit-traceability 13 check-links
→ 14 gen-industry   （新增：由 data/industry.json 生成 companies / industry / events 三页）
```

配套改动：
- `data/industry.json` 加入事实源清单（`upstream-registry.md` 登记）
- `check-links.py` 增加校验：**events 中 `source` 为空即报错**；公司卡片计数与事件流一致
- `rebuild-sitemap.py` 纳入 `/industry/`，并处理 `/papers/` 的去留

## 五、分阶段实施

| 阶段 | 工作量 | 内容 | 产出 |
|---|---|---|---|
| **阶段 1** | 1 轮 | 建 `data/industry.json`；把现有 22 篇行业动态**回录为事件**（每条带 source=对应文章）；清理后的 companies/investors 存量字段迁入静态表 | 种子数据 + 可核查的基线 |
| **阶段 2** | 1 轮 | 写 `gen-industry.py`，接入管线第 14 环节；companies 页改为生成产物 | **手写孤儿页消失** |

**关键顺序**：先数据，后页面（阶段 1→2）。这与本轮的教训正好相反——
之前是「先建页面、内容没跟上」，所以才烂。

## 六、风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 回录 22 篇文章为事件是体力活 | 每条都要标来源与类型 | 阶段 1 可先只回录 A/B 级与近 3 个月，其余逐步补 |
| 上游周报消化仍未自动化 | 阶段 4 若不做，板块仍会停滞 | 阶段 4 至少做成"半自动"：周报落地即提醒录入，不追求全自动 |
| xlsx 结构未确认 | 上游 xlsx 应有结构化字段，可省去人工录入 | **需先读一期 xlsx 确认字段**，若结构良好，阶段 4 可大幅简化 |
| 与另一批次并行 | 已发现 Ops Bot 在 07:55–08:25 推过 3 个提交 | 每次动手前先 `git fetch` 对齐 |

## 七、需要拍板的 4 件事

1. **`/papers/` 砍掉还是重建？** 我倾向**砍掉**——5 篇撑不起栏目，且它与全站 evidence 体系重复。
   若你要保留，就改由 `articles.json` 自动生成 A 级论文索引。
2. **`/investors/` 独立还是并入 companies？** 我倾向**并入**（历史错误率最高，独立价值最低）。
3. **要不要读一期上游 xlsx 确认字段？** 这决定阶段 4 能否自动化。
   需要访问网盘「行业层」`dVEYJcsAbUdK`——属读取，不改动共享资产。
4. **产业板块的目标读者是谁？** 若面向研究者（同行），应强化监管口径与临床进展；
   若面向投资人，应强化融资与管线。**这决定 `/industry/` 的默认筛选维度。**
