## 1. 定位：一档「可以回查」的长寿科学播客

**节目名：《长寿证据链》**（The Longevity Evidence Chain）

Slogan：

> 每期节目，都能顺着一张来源清单回查原文。

长寿内容是互联网上噪声最大的领域之一：补剂营销把「标志物变化」说成「抗衰实证」，
把小鼠寿命延长说成「人类可期」，把利益相关方的论文包装成「重大突破」。
这个站点过去 557 篇解读建立的全部信用，来自一条朴素的原则：
**每个结论都能回到一份可点开的来源**。播客是同一原则的音频形态——

| 我们做 | 我们不做 |
|---|---|
| 讲机制：一个通路「是什么、证据到哪一步」 | 不追时效：不播报「昨日发布」式快讯 |
| 精读论文：一期一篇，按四段式拆解 | 不推荐任何品牌、产品、剂量方案 |
| 产业盘点：只陈述已发生的事实 | 不做投资建议、不谈「该买哪只股票」 |
| 证伪与打假：阴性结果同样值得一期 | 不接商业推广、不做软广（见 §7） |
| 每期附完整来源清单（口播 + 图文） | 不把小鼠数据外推成人类结论 |

**听众画像**：关注抗衰老但被营销话术搞烦了的人；想听懂论文但读不动英文原文的人；
需要向家人/朋友转述「这东西到底有没有证据」的人。

## 2. 为什么是现在：素材已经够了

播客最怕「没内容可讲」。本站现有素材盘点：

| 素材 | 数量 | 对应栏目 |
|---|---|---|
| 文献解读（含 134 篇 A 级人体研究） | 557 篇 | 《论文精读》 |
| 概念词条页（senolytic / 雷帕霉素 / NMN / 端粒…） | 8 个 | 《机制十分钟》 |
| 产业事件（全部带来源） | 40 条 | 《产业脉搏》 |
| 高影响力阴性结果（NOPARK / TAME 等） | 多篇 | 《打假与证伪》 |
| 会议日历 / 监管动态 | 7 场会议 | 《产业脉搏》选题池 |

按「一周一期」排，《论文精读》光 A 级证据就够播两年半——**内容不是瓶颈，
生产链路才是**。本策划的重点是先把链路跑通（§4）。

## 3. 栏目设计（四个系列）

| 系列 | 时长 | 频率 | 内容 | 第一期 |
|---|---|---|---|---|
| **论文精读** | 12–18 min | 每周一期 | A 级人体研究，按「问题→设计→结果→局限」四段式 | ✅ 本期上线 |
| **机制十分钟** | 8–12 min | 每周一期 | 概念词条机制精讲 + 证据边界 | 排期中 |
| **打假与证伪** | 10–15 min | 每月两期 | 阴性试验、营销话术拆解、标志物≠获益案例 | 排期中 |
| **产业脉搏** | 10–15 min | 每月一期 | 月度融资 / 临床 / 监管盘点，只陈述事实 | 排期中 |

自 2026-10-24 起，生产规则改为**每日 03:30 运行，并在 09:00 前上线**。选题池仅限站内已发布、来源清单可回查 DOI/PMID 的文章；以上一轮播客之后的新收录为当日增量。**产能不设上限**：当日合格选题有多少就制作多少，不得为控量硬限期数；若没有合格选题，则记录跳过原因，不以站外材料硬凑。

上线前必须用 `podcast.json` 的历史 `slug / title / article_slugs / DOI` 四路去重；重复选题跳过并记录。每期和播客页面同时展示“数据日期”与“生成时间”，统一采用 `YYYY-MM-DD HH:MM` 格式。

## 4. 单期结构模板（固定骨架，培养听众预期）

每期六个固定环节，顺序不动：

1. **开场（15–20 秒）**：节目名 + 本期一句话概括 + 「本期所有结论附来源，清单在节目末尾」。
2. **正文第一段：问题从哪来**（2–4 分钟）：这项研究/这个机制要回答什么问题，此前证据到哪一步。
3. **正文第二段：证据长什么样**（4–7 分钟）：研究设计（人群/样本量/疗程/终点）→ 结果（数字）。
4. **正文第三段：怎么读**（2–4 分钟）：局限、利益冲突、不能外推什么。
5. **来源清单口播（30–45 秒）**：逐条念期刊 + DOI，语速放慢，方便听众记录。
6. **结尾（15 秒）**：固定免责声明 + 下期预告。

固定免责声明（每期必播）：

> 本节目内容基于公开发表的研究，只作信息汇总，不构成医疗建议。
> 任何干预决定，请咨询医生。

## 5. 技术方案

### 5.1 数据流

```
data/podcast.json（事实源，手工维护）
      │
      ├─→ scripts/gen-podcast.py ─→ /podcast/index.html（节目列表 + 播放器 + shownotes）
      │                          └─→ podcast.xml（RSS 2.0 + iTunes 扩展，供各平台订阅）
      │
      └─→ scripts/synth_podcast_audio.py（手动运行，仅在新增期目时执行）
                └─→ audio/<slug>.mp3（合成后入 git，管线不重合成）
```

**设计决定：音频是「发布物」不是「构建物」。** TTS 依赖外部服务（edge-tts 走微软
Edge 语音端点，无 SLA），每次管线重合成会让同一文稿产出不同音频、且网络波动会
阻断整条管线。所以：文稿定稿 → 手动合成一次 → mp3 入 git → 管线只做「页面 +
RSS 生成」与「音频存在性校验」。新增期目时跑一次 synth 脚本即可。

### 5.2 事实源 schema（data/podcast.json）

```json
{
  "schema": 1,
  "show": {
    "title": "长寿证据链",
    "tagline": "每期节目，都能顺着一张来源清单回查原文。",
    "author": "LongBiosci 编辑部",
    "language": "zh-cn",
    "explicit": false,
    "category": "Science",
    "site_url": "https://longbiosci.com/podcast/",
    "rss_url": "https://longbiosci.com/podcast.xml",
    "cover": "https://longbiosci.com/podcast-cover.png",
    "copyright": "© 2026 LongBiosci 编辑部",
    "disclaimer": "本节目内容基于公开发表的研究，只作信息汇总，不构成医疗建议。"
  },
  "episodes": [
    {
      "id": "ep001",
      "slug": "nad-precursor-nr-nmn-headtohead",
      "series": "论文精读",
      "title": "NAD⁺ 前体之争：标志物翻倍之后，发生了什么",
      "date": "2026-10-19",
      "duration_sec": 780,
      "audio": "audio/nad-precursor-nr-nmn-headtohead.mp3",
      "desc": "三句话以内的列表页摘要。",
      "shownotes": "完整 shownotes（Markdown 子集：段落 / 列表 / 链接）。",
      "article_slugs": ["news/NAD-Precursor-Head-to-Head-RCT-NR-NMN-2026.html", "..."],
      "sources": [
        {"label": "Nature Metabolism（2026）", "doi": "10.1038/s42255-025-01421-8", "pmid": "41540253"}
      ]
    }
  ]
}
```

硬规则（与产业事件流同源）：

- 每期 **必须**带 `sources`，且每条来源至少含 DOI 或 PMID；缺失时生成器直接告警跳过——杜绝「播客凭空杜撰」；
- `article_slugs` 引用的站内文章必须存在（生成器校验，缺失即报错）；
- `duration_sec` 由合成时 ffprobe 实测回填，不手填；
- 每期和页面必须带 `data_datetime` 与 `generated_at`，格式固定为 `YYYY-MM-DD HH:MM`；
- 上线前按历史 `slug / title / article_slugs / DOI` 去重，重复期目跳过并告警。

### 5.3 音频生产

- 引擎：edge-tts 7.3.1（Microsoft Edge 在线语音，免费，无需 API key）
- 音色：`zh-CN-XiaoxiaoNeural`（暖调女声，News/Novel 风格，适合叙述型科普）
- 语速：+5%（信息密度优先，但不赶）
- 环境：edge-tts 装在系统 Python 3.12；合成时用 `/usr/bin/python3.12` 显式调用
- 实测：48 kbps mp3，约 0.45 MB/分钟——10 分钟一期约 4.5 MB，git 可承受

## 7. 合规与风险边界

1. **非医疗建议**：每期固定口播 + shownotes 常驻声明。
2. **不推荐产品**：节目不出现任何品牌名作为推荐；研究涉及的商品名仅在陈述
   研究设计时出现（如「Niagen Bioscience 持有 NR 专利」这类利益冲突披露）。
3. **不接商业推广**：播客不做软广、不接补剂商赞助——这是本站证据信用的延伸，
   开这个口子等于把 §1 的定位作废。
4. **版权**：口播内容全部来自站内已发布原创解读 + 已引文献的摘要级信息，
   不朗读付费墙全文；每期逐条念 DOI，听众可自行核对。
5. **TTS 服务依赖**：edge-tts 是微软免费端点，无 SLA。缓解：音频合成后即入 git，
   站点永不依赖实时 TTS 服务；若端点失效，只影响新增期目，存量节目不受影响。
6. **音频托管**：GitHub Pages 无带宽保证。当前体量（每期 < 5 MB）下风险可控；
   若单期下载量持续过千，再评估对象存储/CDN（届时先征询用户意见，涉及可能的花费）。
