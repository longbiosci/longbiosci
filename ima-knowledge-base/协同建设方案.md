## 一、诊断：三个真实问题

### 问题 1｜B 线在原地打转，已连续 3 轮

`文献库建构进度报告_2026-10-12.md`（R4轮）里三个数字互相矛盾：

| 指标 | R3 (10-05) | R4 (10-12) | 问题 |
|---|---|---|---|
| 库内总篇数 | 134（09-24 实测） | **134（连续第 3 轮未能复测）** | ⚠️ 沿用3 周前的旧值 |
| 著录率 | 133/133 = 100% | 133/133 = 100% | ⚠️ **分子分母同源**，不构成证据 |
| 年份×标志矩阵 | 86/98 | 98/98 ✅ |✅ 真实进展 |
| 速递层待复测 | 82 条 | **118 条（+36）** | ⚠️ 每轮新增却无法确认入库 |

**判断**：矩阵贯通是**检索端**的胜利；归档端处于空转状态。
「著录率 100%」是拿本地 133 篇除以本地 133 篇算出来的自我循环，
真实库内 310 篇里究竟有多少已完成著录，**当前无法回答**。

⚠️ 报告自身已诚实标注此口径（§一 补充说明），并坚持把 118 条标为 `digest`
而非「已归档」——**这个克制是对的，不要改**。问题在于通道何时能通。

### 问题 2｜A 线产出枯竭，根因不在执行质量

近四期新增条数：

```
10-10: 7 条 → 10-11: 5 条 → 10-12: 2 条 → 10-13: 3 条
```

10-13 期日志给出了确切原因：窗口内 261 条并集，**仅 2 条命中标题级主词表**。
bioRxiv 每日 posting 约 200 条，但衰老/长寿是**窄口径**——
真正命中的是细胞衰老、表观时钟、senolytic 这类具体词。

**判断**：这不是执行质量问题，是**选题池见底**。继续靠扩词表提量，
假阳性率会快速反弹（历史上朴素匹配曾达 77%）。
**必须扩信源，不能只扩词表。**

### 问题 3｜三条线零交叉，而本该有交叉

- A 线每天产出 3–7 篇**带完整结构化字段**的预印本评估
  （核心要点 / 保留意见·局限 / 对我的价值 / 溯源双源）
- C 线每天需要 3 篇同主题深度解读发到站上

**但 10-13 发出的三篇（心磷脂-ERRγ、拉曼检测、Lsp2）全部是临时联网检索**，
而 A 线总表里躺着 166 篇带 DOI、带保留意见的现成素材。

**这条管道现在完全没接。** 每天重复劳动，且A 线的「保留意见」这种
最稀缺的分析资产被浪费在只读的日报里。

## 二、方案：四步走（先止损 → 再提效 → 后扩张）

### 第 1 步｜打通 IMA 通道 ★最高优先级

**问题**：B 线报告称 IMA MCP 工具未注入，`ToolSearch` 探活返回空。
2026-10-13 实测确认：当前工具列表中**无 IMA 相关工具**，
在线连接器仅 `agent-mail`、`sungo-device-registry`（tmeet 未授权）。

**影响面**：三线最终校验全部悬空。A 线能写库是因为某轮通道短暂可用过
（10-13 待归档清单记录「订阅库 total_size 301 → 310」，说明**当时是通的**），
说明这是**间歇性授权失效**，不是从未配置。

**动作**：
1. 在聊天窗口左下角「+」菜单中检查 IMA 连接器是否已安装、是否需要重新授权
2. 若已安装未连接 → 开启；若未安装 → 用 `search_plugins` 找 IMA 后安装
3. 若走 MCP 路径 → 检查 `~/.workbuddy/mcp.json` 中 IMA server 条目，
   在连接器管理页右上角点「信任」

**验收**：能一次调 `get_knowledge_list(7505141192201969)` 拿到真实条数。
**成本**：点一次菜单。**收益**：B 线从空转转为可验证推进。

> ⚠️ 不要用「本地台账代理」长期替代通道。当前 B 线用
> `_up_master.xlsx` + DOI 差集做本地代理是**合理的应急**，
> 但它无法回答「库内到底有没有这篇」——这是归档的最后一米，必须靠通道。

### 第 2 步｜建「共享层」：一个 DOI 口径打通三线

**2.1 先做一次全量对账（一次性，1 小时）**

```
速递总表 166 条  ×  老文献索引 302 条  →  按 DOI 求差集
```
产出三张清单：
- **重叠**：两线都收录 → 优先做速递层的全文归档（已有PDF，成本最低）
- **速递独有**：A 线有、B 线无 → B 线补著录的天然候选
- **老文献独有**：B 线回溯成果 → 可反哺 A 线的历史脉络

**2.2 建两个自动化**

| 自动化 | 调度 | 职责 |
|---|---|---|
| **选题池同步** | 每日 09:45（速递跑完后 15 分钟） | 读当日速递总表增量 → 写入选题池文件 → 供 C 线取用 |
| **判重回写** | 每周一 11:00（B 线跑完后） | 比对 C 线已发文章 slug → 在速递总表加「已发站点」列 |

**2.3 改造 C 线取数逻辑**

今日 C 线的做法是「WebSearch + freshness 限 1–3 天」。
**改为：先查选题池（A 线今天筛过的条目），不够再补联网检索。**

预期收益：每日省去大量重复检索，且 C 线的深度解读可以直接继承A 线的
「保留意见/局限」——**这正是本站编辑方针最看重、也最难自己憋出来的部分**。

### 第 3 步｜拓宽信源池（应对 A 线枯竭）

**3.1 加三个新信源**

| 信源 | 补的是哪块缺口 | 优先级 |
|---|---|---|
| **medRxiv 临床口径** | 现在硬剔除（`institution==bioRxiv`），但临床衰老试验大量发在medRxiv | ★★★ |
| **ClinicalTrials.gov 招募中** | 填补「有信号但未发表」的空白，与 B 线天然互补 | ★★★ |
| **Nature Aging / Cell 在线优先** | 同行评议但尚未进PubMed，**可把 A 线的预印本升级为 A 级** | ★★ |

**3.2 按主题分频，替代每日全量**

当前每天扫全量 + 用单一主词表筛，导致「261 条里只命中 2 条」。
改为**主题轮值**：

```
周一 细胞衰老 / senolytic
周二 表观遗传时钟 / 生物年龄
周三 干预手段（雷帕霉素/NMN/二甲双胍/proteostasis）
周四 器官衰老 / 神经退行
周五 免疫衰老 / 炎症衰老
周末 空窗或补漏
```

**关键**：检索窗口口径**不变**（仍按 Crossref `created`，这是 10-13 期
固化的规则 30，已验证能防漏稿）。改的只是**主词表按主题切换**。
这样每日词表可精、假阳性率低，且一周覆盖全部主题。

### 第 4 步｜扩到对外交付（资产复利）

1. **速递总表加「已发站点」列** —— 命中则站内挂内链，未命中则转为 C 线选题。
   **一份总表同时驱动「情报」与「内容」两个出口。**
2. **季度主题综述** —— 从 302 条索引按年份×标志矩阵聚合，
   自动生成「某标志的 60 年演进脉络」。这比逐篇阅读省 90% 时间，
   且这是**只有总索引才能做的事**，单篇速递做不到。
3. **清理遗留**：
   - 云端 `cloud:7762987`「预印本速递·每日」保持 PAUSED，
     需在 App「项目 → 衰老和长寿情报 → 自动化」中**手工删除**（本机 API 只读）
   - IMA App 内手工删除测试遗留的「网址」条目
     `https://www.biorxiv.org/content/10.64898/2026.09.17.752532v1.full.pdf`
   - 补齐 2026-09-24 产出的总表与简报到项目资产（当时工具未注入未回写）

## 四、必须守住的红线（沿用 A 线规范）

1. **数据真实可溯源，禁止编造**；无法核实一律填「未列」
2. 预印本引用须标注「**预印本 · 未同行评审**」并带版本号
3. **不得改动总表 Z 列「个人评注」**（用户自留地）
4. 项目资产任何写入需先展示改动并获确认
5. **通道缺失时不得把 `digest` 写成「已归档」** —— 这条B 线已经守住了，
   新增自动化也必须继承
6. 真实无新条目时仍需写空跑说明，**不得省略、不得臆造**

## 五、需要用户决策的点

1. **主题分频方案是否采纳？** 会改变速递的产出节奏（每日全量 → 单主题）
2. **是否接入 medRxiv？** 意味着不再硬剔除非bioRxiv 源，
   但会引入临床口径的条目，筛选词表需相应调整
3. **季度主题综述是否需要？** 属新增交付物，需确认是否值得投入
4. **IMA 通道的开启方式** —— 需要用户在 UI 侧操作，本机无法代劳
