## 二、每轮固定九步（幂等 · 漏跑自动顺延）

**Step 0 · 前置读盘**
读规范 `_out\衰老文献库建构规范_v2_时间×标志矩阵.md`；读上一版索引的「缺口与下一步」工作表 → 得到本轮目标（年份段 + 待补标志集合）。

**Step 1 · 增量同步**
`get_knowledge_list(7505141192201969, limit=50)` **必须翻页至 `is_end=true`**（当前 133 条 = 3 页）→ 得到全库条目。
与索引 `media_id` 列比对，**库里新出现但索引未收录的条目先补著录**（保证每日速递的新归档被并入）。

**Step 2 · 缺口计算**
打开索引「年份×标志矩阵」（`7 年份段 × 14 标志 = 98 格`），按规范 2.2 的倒序优先（`Y2026 → Y2025 → Y2020-Y2024 → …`）选出本轮年份段，段内优先 `0` 值格，其次低值格。

**Step 3 · 定向检索**
对每个目标 `(年份段, 标志)` 组合检索代表作，优先级：**奠基文献 → 权威综述 → 里程碑原始研究 → 最新进展**。
源：Europe PMC REST、Crossref、PubMed E-utilities、bioRxiv/medRxiv、期刊官网。
（注：bioRxiv 官方 details API 已失效、arXiv API 返回 406 —— 沿用既有降级方案：Crossref 主源 + 站点 feed + Europe PMC 校验。）

**Step 4 · 筛选去重**
去重键 = **DOI**（无 DOI 用 `media_id`）。对全库现有条目 + 索引做双重比对，命中即跳过。
每轮目标入库 **8–12 篇**（按段内 14 标志均衡分配）。

**Step 5 · 全文获取**
优先 OA（PMC / 出版商 OA / 预印本 PDF）；非 OA 尽力取（用户已定「不限 OA，尽量取全文」）。
确实取不到 → **只著录元数据**，在索引「全文可得性」列写「仅元数据」，**不得虚构**。

> **bioRxiv 取全文要点（2026-09-24 实测）**
> - bioRxiv 迁 openRxiv 后新 DOI 前缀是 **`10.64898/YYYY.MM.DD.NNNNNN`**（旧为 `10.1101/`）。
>   **URL 规则不变**：`https://www.biorxiv.org/content/{完整DOI}v{n}.full.pdf`。用旧前缀拼的 URL 会 302 到
>   `/node/.full-text.pdf` 然后 **429**，别误判为站点故障。
> - **节奏：75 s/次起步；命中 429 退避 130 s、最多 4 次。** 限速紧时一篇要 2 次重试（≈5 min），6 篇约 15–20 min，
>   要留足时间预算，**不要压缩间隔**（会连环 429）。
> - 校验 `data[:4] == b"%PDF"` 且 `size ≥ 50000`；目标文件已存在且达标即跳过（断点续跑零成本）。
>
> **★ 全文首选通道（2026-09-28 实测，优先级最高）**
> - **`https://www.ebi.ac.uk/europepmc/webservices/rest/{PMCID}/fullTextXML` 是本环境唯一稳定可达的全文通道（200）**，
>   比 Unpaywall / 出版社直链更可靠。**先查它，再考虑别的**。
> - 拿到 JATS XML 后用 `reportlab` 渲染成 PDF（Arial Unicode 字体；脚本见 `_src\dl_r4.py`）。
>   **必须在 PDF 首页写「转载与来源说明」**：注明来源为 Europe PMC OA 全文 XML、非出版商排版件、图表以题注文字保留。
>   并在索引「保留意见 / 局限」列同步注明，不得让读者误以为拿到的是原版 PDF。
> - 该接口对「仅作者稿」的 PMC 记录（`isOpenAccess=N`）返回 **500**，对无 PMC 记录的文章不存在 → 这两种情况才判「仅元数据」。
> - **实测不可达（2026-09-28 复核，不必重复探测）**：`pmc.ncbi.nlm.nih.gov` 连接超时、`nature.com`(→idp.nature.com) 超时、
>   `rupress.org` 403、`sciencedirect.com` 403、`europepmc.org/api/fulltextRepo` 连接重置。

**Step 6 · 归档入库**
`create_media` → COS `put_object`（**bucket/region 一律取 create_media 返回值**）→ `add_knowledge`。
命名 `Y{年份}_{H代码}_{中文标题}.pdf`（增量层维持 `{期次}_{层级}_{中文标题}.pdf`）。批量 5–8 篇一次，凭证不可复用上一批。

**Step 8 · 回写三处**

## 三、质量红线

1. **真实可溯源**：年份 / DOI / 期刊 / 作者一律来自 Crossref、Europe PMC、PubMed、期刊官网或速递总台账。**解析不到就写「未解析」，禁止推测、禁止编造。**
2. Crossref 标题检索相似度 < 0.75 的条目进「待人工复核」，不直接采信。
3. **个人评注列**（索引末列）是用户自留地，自动化与 WorkBuddy 一律**禁止覆盖**。
4. 临床试验一律以 ClinicalTrials.gov 等官方来源为准。
5. **不伪造成功**：工具未注入 / 上传失败要原件留在工作区，并在报告里写明缺哪条通道、补做命令。

## 四、Windows 环境硬约束（本机实测）

- **bash 工具的可用性逐会话不同**：多数会话连 `mkdir`/`ls` 都 `command not found`（shim 挂在 `dirname`），
  但 2026-09-24 补齐轮实测 **bash 完全可用**（含 `curl.exe`、`sleep`、`tee`）。
  → **先探活再用**：跑一句 `echo ok` 判断；不可用就退回 PowerShell。
- PowerShell 工具**禁止调用 `cmd.exe`**（安全策略拦截）。
- PowerShell **stdout 回传不稳定** → 重要输出一律 `Out-File -Encoding UTF8` 到文件再 Read。
- 含中文的 `.ps1` 必须存 **UTF-8 带 BOM**；控制台编码 cp936。
- 需要 curl 用 `curl.exe`（系统自带）。**长 token / 长签名 URL 绝不能手抄进命令行**：
  一律用 `Write` 工具把完整命令落成 `.sh` 或 `curl -K` 配置文件再执行
  （手抄会被截断 → `InvalidAccessKeyId`）。
- IMA / 网盘 MCP 工具**可能在某些会话未注入** → 先用 `ToolSearch` 精确探活（见 skill `wb-asset-upload` §0.1）。
